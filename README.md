# jradio

Прошивка стационарного аудиоплеера на ESP32-S3 (ESP-IDF 5.5.x): интернет-радио
и воспроизведение файлов с USB-флешки. Управление — энкодером и четырьмя
функциональными кнопками на экране устройства либо через веб-интерфейс в
локальной сети.

## Состояние режимов

| Режим | Статус |
|---|---|
| Интернет-радио | Работает: MP3, AAC, FLAC, Ogg FLAC, HTTP и HTTPS, ICY-метаданные, плейлист, автозапуск последней станции, переподключение |
| USB-плеер | Работает: браузер каталогов на экране и в вебе, MP3, AAC, FLAC, Ogg FLAC, WAV, автопереход к следующему треку |
| Wi-Fi provisioning | Работает: настройка через временную точку доступа, до пяти сохранённых сетей |
| Веб-интерфейс | Работает: плеер, браузер флешки, настройки, редактор плейлиста; живое состояние по WebSocket |
| Экранный интерфейс | Работает: главный экран (список или лента), экран плеера, списки станций и файлов |
| Экран настроек | Работает: группы «Язык», «Общие», «Экран»; сохранение в `settings.csv` |
| DLNA | Не реализован |
| FM-радио | Не реализован, микросхема не выбрана |
| Bluetooth | Не реализован, микросхема не выбрана |
| RTC DS3231 | Не реализован, GPIO для I2C не назначены |
| OTA | Раздел в таблице разделов есть, механизм обновления не реализован |
| Яндекс Музыка | Отложено до выяснения допустимого способа интеграции |

Экран «Настройки» содержит раскрывающиеся группы `Язык`, `Общие` и `Экран`.
Изменения применяются сразу и сохраняются в `/littlefs/config/settings.csv`.
Настройки: язык (`ru`/`en`), главный экран (`text`/`feed`) и независимые
переключатели вертикального и горизонтального отражения дисплея. Выход с
экрана — F2 либо удержание кнопки энкодера дольше 800 мс.

Переключатель языка пока меняет подписи **только на самом экране настроек**;
главный экран, плеер и списки остаются с фиксированными подписями.

## Управление на экране плеера

Кнопка энкодера закрывает все три действия, F2 и F3 продолжают работать как
раньше:

| Жест | Действие |
|---|---|
| Короткое нажатие | Пауза / воспроизведение |
| Двойное нажатие | Список станций или файлов, воспроизведение продолжается |
| Долгое нажатие (0,8 с) | Главный экран, воспроизведение останавливается |

Одиночное нажатие срабатывает через 350 мс: раньше этого момента невозможно
отличить его от первой половины двойного. Двойное, наоборот, срабатывает
сразу. Задержка действует **только на экране плеера** — меню, списки и
настройки отвечают на нажатие немедленно.

В режиме главного экрана `feed` отображается горизонтальная лента из семи
функций: интернет-радио, USB, Bluetooth, FM, DLNA, Яндекс Музыка и настройки.
Поворот энкодера перемещает выбранную иконку, короткое нажатие открывает
функцию, а ещё не реализованные режимы показывают заглушку «Функция пока
недоступна». Режим `text` сохраняет вертикальное меню.

## Текущая архитектура

Аудиотракт не использует полный ESP-ADF/ESP-GMF pipeline. Источник потока
(`internet_radio` или `usb_player`) выполняет чтение и буферизацию данных, а
декодирование выполняется специализированными компонентами: `micro-mp3`,
`micro-flac` и `espressif/esp_audio_codec` для AAC и остальных поддержанных
форматов. Декодированный PCM передаётся через общий аудиовыход платы на
PCM5102 по I2S. Это фактическая реализация проекта и не требует внешнего
`ADF_PATH`.

Управление из браузера и с устройства проходит через общий `player_control`.
Команды и живые изменения состояния передаются по двунаправленному
WebSocket `/ws`. Большие данные — полный плейлист и содержимое каталогов USB —
передаются через REST (`/api/playlist` и `/api/usb`), поскольку они не
помещаются в ограниченный WebSocket-кадр и не должны увеличивать расход
внутренней SRAM. Таким образом, WebSocket является транспортом управления и
состояния, а REST — транспортом объёмных списков и совместимых HTTP-запросов.

## Оборудование

- ESP32-S3 в корпусе QFN56, 16 МБ flash, 8 МБ PSRAM;
- дисплей ILI9341 320×240 по SPI;
- поворотный энкодер с кнопкой и четыре функциональные кнопки;
- ЦАП PCM5102 по I2S, линейный выход;
- порт USB Host для флешки в файловой системе FAT.

### Распиновка

Ревизия платы 1. Значения заданы в [`board_options.h`](board_options.h) в корне
проекта — он и остаётся источником истины, таблица ниже приведена для удобства.

Настройки в нём сгруппированы по физическим устройствам: экран, подсветка,
органы управления, звуковой выход, USB. В каждой группе одной строкой выбрана
микросхема и перечислены её выводы, так что при повторении платы или переносе
узла на другие контакты правится только этот файл:

```c
#define DISPLAY   DISPLAY_ILI9341_320
#define AUDIO_DAC DAC_PCM5102
```

Допустимые значения перечислены в
[`components/board/include/board_parts.h`](components/board/include/board_parts.h) —
это список деталей, для которых в прошивке есть драйверы. Опечатка или выбор
неподдерживаемой микросхемы приводит к ошибке сборки, а не к неработающему
устройству.

Всё, что **следует** из выбора детали — разрешение матрицы, ориентация, формат
отсчётов I2S, геометрия буфера DMA, — задано в профилях
`board_display_profile.h` и `board_audio_format.h` рядом с драйвером. Это
свойства самой микросхемы, а не решения по разводке платы, поэтому в
`board_options.h` их нет.

| Узел | GPIO | Примечание |
|---|---:|---|
| ILI9341 CS | 10 | SPI |
| ILI9341 DC | 47 | SPI |
| ILI9341 MOSI | 11 | SPI |
| ILI9341 SCLK | 12 | SPI |
| ILI9341 RST | — | соединён с reset ESP32, GPIO не занимает |
| Подсветка ILI9341 | 2 | ШИМ |
| Энкодер вправо | 5 | внешний подтягивающий резистор |
| Энкодер влево | 7 | внешний подтягивающий резистор |
| Кнопка энкодера | 6 | внешний подтягивающий резистор |
| F1 | 45 | внешний подтягивающий резистор |
| F2 | 21 | внешний подтягивающий резистор |
| F3 | 46 | внешний подтягивающий резистор |
| F4 | 9 | внешний подтягивающий резистор |
| PCM5102 DOUT | 16 | I2S data |
| PCM5102 BCLK | 18 | I2S bit clock |
| PCM5102 LRCK | 17 | I2S word select |
| USB D− | 19 | встроенный USB PHY |
| USB D+ | 20 | встроенный USB PHY |

Особенности, важные при повторении платы:

- линии MISO у дисплея нет, обмен односторонний; матрица требует порядка BGR;
- PCM5102 работает без MCLK, слоты I2S 16-битные стерео,
  BCLK = 32 × Fs. Буфер DMA — 8 × 512 кадров, около 93 мс: эта геометрия
  подобрана против щелчков, уменьшать её не следует;
- аппаратного подавления дребезга нет, оно сделано программно;
  внутренние подтяжки включены дополнительно к внешним, без них GPIO 45, 46
  и 21 вели себя нестабильно;
- у модуля PCM5102 вывод SCK должен быть притянут к земле, а XSMT — к 3,3 В.
  Висящие в воздухе, они дают редкие и трудноуловимые пропадания звука при
  полностью исправном цифровом тракте;
- VBUS порта USB запитан постоянно и прошивкой не управляется. Отдельный GPIO
  для этого не нужен: накопитель, оставшийся на шине после перезагрузки
  ESP32, переопределяется логическим циклом питания корневого порта
  (`usb_host_lib_set_root_port_power()`), который переключает бит `PRTPWR`
  контроллера, а не внешнюю линию.

## Сборка и прошивка

Активируйте ESP-IDF, затем:

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p PORT flash              # только приложение, LittleFS не затрагивается
idf.py -p PORT littlefs-flash     # перезаписывает раздел данных целиком
idf.py -p PORT monitor
```

`littlefs-flash` записывает каталог `data/` целиком и **уничтожает
пользовательские данные на устройстве** — правки плейлиста и сохранённые
Wi-Fi-сети. Перед запуском сверьте живое состояние с репозиторием:

```bash
curl http://<ip>/api/playlist
```

## Тесты

```bash
bash tests/run_host_tests.sh
```

40 наборов тестов, ESP-IDF активировать не нужно. Тесты компилируют настоящие
исходники компонентов, а не заглушки, с `-Werror` и санитайзерами адресов и
неопределённого поведения. Поэтому разбор форматов, конечные автоматы и вывод
представлений вынесены в отдельные файлы без зависимостей от ESP-IDF —
новую логику следует добавлять туда. Браузерный JavaScript проверяется под
Node с рукописным поддельным DOM, без npm и сборщиков.

## Веб-интерфейс

Страница плеера доступна по адресу устройства в локальной сети. Живое
состояние приходит по WebSocket `/ws` диффами: кадр ограничен 512 байтами на
приём и 4 КБ на отдачу, поэтому всё крупное вынесено в обычный REST.

| Точка | Назначение |
|---|---|
| `GET /api/status` | Состояние Wi-Fi и плеера одним снимком |
| `GET /api/playlist` | Список станций в CSV |
| `POST /api/playlist` | Замена списка станций целиком |
| `GET /api/usb` | Содержимое текущего каталога флешки |
| `POST /api/wifi` | Сохранение сети |
| `/ws` | Команды и живые обновления |

Команды WebSocket: `player.play`, `player.pause`, `player.toggle`,
`source.select` (`internet_radio` или `usb`), `list.select` с номером строки,
`browse.up` для выхода из каталога, `wifi.save`.

Список файлов флешки намеренно не передаётся по WebSocket: каталог из 256 имён
по 256 байт не помещается в кадр, а увеличивать статический буфер при дефиците
внутренней SRAM неразумно. Вместо этого по сокету идёт только заголовок с полем
`revision`, а сами записи браузер забирает через `GET /api/usb` потоково.
Номер ревизии возвращается и в ответе — по нему клиент отбрасывает ответ на
каталог, который пользователь уже покинул.

## Диагностика звука

Пропадания звука не оставляют следов сами по себе: плеер продолжает
докладывать `playing`, а API не меняет состояние. Поэтому прошивка раз в
10 секунд пишет в журнал две строки — по одной на общий вывод и на приём
потока:

```
board: audio health: realtime=100% peak=21533 silent=0 zero_run=0 underruns=0 writes=384 short=0
internet_radio: stream health: i2s_underruns=0 starvations=0 min_backlog=32768/65536 (1024ms) pcm=100%
```

Как читать:

- `realtime` — доля реального времени, фактически отданная в ЦАП. Падение
  означает, что запись прекратилась;
- `peak` — максимальная амплитуда за окно, `silent` — блоки из одних нулей,
  `zero_run` — самая длинная непрерывная серия нулевых кадров. Последнее важно
  само по себе: PCM5102 включает аналоговое приглушение после 1024 нулей
  подряд, и по границам блоков такая серия иначе не видна;
- `underruns` — опустошения DMA, слышимые как щелчок или провал;
- `min_backlog` — наименьший запас перед декодером за окно. Значение в
  миллисекундах информативнее байтов: 32 КБ — это секунда MP3 128 кбит/с, но
  всего 181 мс потока FLAC.

Отдельные предупреждения `audio gap`, `audio silence` и `audio zero-run`
фиксируют точный момент события, а не окно целиком.

Полностью исправная картина: `realtime` 99–100 %, `peak` порядка 21000–23000,
все остальные счётчики нулевые. Если при этом звука нет — неисправность после
передачи данных в DMA, то есть в обвязке ЦАПа, а не в прошивке.

## Данные на устройстве

Раздел `littlefs` хранит и статику веб-интерфейса, и пользовательские данные:

- `data/www/` — `index.html`, `app.js`, `style.css`; при сборке
  предварительно сжимаются в gzip;
- `data/config/stations.csv` — список станций;
- `data/config/settings.csv` — настройки в формате `key,value`;
- `wifi.json` — создаётся устройством, в Git не входит.

Не добавляйте в репозиторий Wi-Fi-пароли, токены и другие ключи.

## Известные ограничения

- **Не более 256 записей в одном каталоге флешки** (`USB_STORAGE_MAX_ENTRIES`).
  Лишние отбрасываются с предупреждением в журнал. Считаются только видимые:
  папки и файлы поддерживаемых форматов. Значение можно поднять, каждая
  запись стоит около 264 байт в PSRAM.
- **Только FAT32 или FAT16.** exFAT не собран (`FF_FS_EXFAT = 0`), а флешки от
  64 ГБ обычно приходят с завода в exFAT и требуют переформатирования.
- **Веб-интерфейс рассчитан только на доверенную локальную сеть.**
  Аутентификации нет, проверка заголовка `Origin` не выполняется. Не открывайте
  устройство наружу.
- Свободной внутренней SRAM мало. Крупные буферы выделяются в PSRAM с откатом
  во внутреннюю память — этот откат нужно сохранять при добавлении новых.
