# jradio

Прошивка стационарного аудиоплеера на ESP32-S3 (ESP-IDF 5.5.x): интернет-радио
и файлы с USB-флешки. Управление энкодером и четырьмя кнопками на экране
устройства либо из браузера в локальной сети.

*[English version](README.en.md)*

## Возможности

| Режим | Состояние |
|---|---|
| Интернет-радио | MP3, AAC, FLAC, Ogg FLAC, HLS (`.m3u8`); HTTP и HTTPS; ICY-метаданные; плейлист; переподключение |
| USB-плеер | Браузер каталогов; MP3, AAC, FLAC, Ogg FLAC, WAV; автопереход к следующему треку; позиция в треке |
| Громкость | Цифровая, ручкой энкодера, сохраняется |
| Часы | По SNTP, на всех экранах |
| Wi-Fi | Настройка через временную точку доступа, до пяти сохранённых сетей |
| Веб-интерфейс | Плеер, браузер флешки, настройки, редактор плейлиста; живое состояние по WebSocket |
| Экраны | Главный (список или лента), плеер, списки станций и файлов, настройки |
| Автовоспроизведение | Восстанавливает станцию или файл, игравшие до выключения |
| DLNA, FM, Bluetooth, RTC, OTA | Не реализованы |

Настройки (`Язык`, `Общие`, `Экран`) применяются сразу и сохраняются в
`/littlefs/config/settings.csv`: язык, вид главного экрана, автовоспроизведение,
независимые отражения дисплея по вертикали и горизонтали, громкость.
Переключатель языка пока меняет подписи **только на самом экране настроек**.

## Экран плеера

Сверху полоса состояния: часы по центру, уровень Wi-Fi справа четырьмя
полосками с числом в дБм. До первой синхронизации по SNTP часы показывают
`--:--` — часов реального времени в устройстве нет.

Ниже место под обложку, название станции, крупная строка трека и исполнитель:
заголовок ICY делится по первому тире с пробелами по обе стороны, при любой
неоднозначности остаётся целым.

Внизу заполнение входного буфера (для файла — время и полоса позиции) и
громкость, между ними индикатор уровня по каналам: 20 кубиков, верхняя пятая
часть красная. Шкала логарифмическая, 20 дБ от −5 до −25 dBFS; измеряется не
пик, а максимум среднеквадратичного по окнам 5,8 мс. **Уровень снимается до
регулятора громкости** — иначе убавленный звук выглядел бы как просевший поток.
Пауза показывается значком по центру экрана.

Все экраны используют одну палитру и одну полосу состояния.

## Управление

| Жест | Действие |
|---|---|
| Поворот энкодера | Громкость на экране плеера, перемещение по спискам |
| Короткое нажатие | Пауза / воспроизведение |
| Двойное нажатие | Список станций или файлов, воспроизведение продолжается |
| Долгое нажатие (0,8 с) | Главный экран, воспроизведение останавливается |

Одиночное нажатие срабатывает через 350 мс — раньше его не отличить от первой
половины двойного. Задержка действует только на экране плеера.

## Оборудование

ESP32-S3 QFN56, 16 МБ flash, 8 МБ PSRAM; дисплей ILI9341 320×240 по SPI;
поворотный энкодер с кнопкой и четыре кнопки; ЦАП PCM5102 по I2S с линейным
выходом; порт USB Host для флешки в FAT.

Распиновка задана в [`board_options.h`](board_options.h) — он источник истины,
таблица ниже для удобства. Настройки сгруппированы по устройствам; деталь
выбирается одной строкой, а всё, что из неё следует, лежит в профилях рядом с
драйвером:

```c
#define DISPLAY   DISPLAY_ILI9341_320
#define AUDIO_DAC DAC_PCM5102
```

Допустимые значения — в
[`board_parts.h`](components/board/include/board_parts.h). Опечатка приводит к
ошибке сборки, а не к неработающему устройству.

| Узел | GPIO | | Узел | GPIO |
|---|---:|---|---|---:|
| ILI9341 CS | 10 | | Кнопка энкодера | 6 |
| ILI9341 DC | 47 | | F1 | 45 |
| ILI9341 MOSI | 11 | | F2 | 21 |
| ILI9341 SCLK | 12 | | F3 | 46 |
| Подсветка | 2 | | F4 | 9 |
| Энкодер вправо | 5 | | PCM5102 DOUT | 16 |
| Энкодер влево | 7 | | PCM5102 BCLK | 18 |
| USB D− | 19 | | PCM5102 LRCK | 17 |
| USB D+ | 20 | | | |

RST дисплея соединён с reset ESP32 и GPIO не занимает.

Важное при повторении платы:

- MISO у дисплея нет, обмен односторонний; матрица требует порядка BGR;
- PCM5102 работает без MCLK, слоты I2S 16-битные стерео, BCLK = 32 × Fs.
  Буфер DMA 8 × 512 кадров (~93 мс) подобран против щелчков, уменьшать нельзя;
- **SCK модуля PCM5102 притянуть к земле, XSMT — к 3,3 В.** Висящие в воздухе,
  они дают редкие пропадания звука при полностью исправном цифровом тракте;
- подавление дребезга программное. Внутренние подтяжки включены у кнопок
  (без них GPIO 45, 46 и 21 нестабильны) и выключены у энкодера, где хватает
  внешних;
- VBUS порта USB запитан постоянно; накопитель, оставшийся на шине после
  перезагрузки, переопределяется логическим циклом питания корневого порта.

## Сборка и прошивка

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p PORT flash              # только приложение, LittleFS не трогает
idf.py -p PORT littlefs-flash     # перезаписывает раздел данных целиком
idf.py -p PORT monitor
```

`littlefs-flash` **уничтожает пользовательские данные** — правки плейлиста и
сохранённые сети. Перед запуском сверьте живое состояние:
`curl http://<ip>/api/playlist`.

## Тесты

```bash
bash tests/run_host_tests.sh
```

44 набора, ESP-IDF активировать не нужно. Тесты компилируют настоящие исходники
компонентов, а не заглушки, с `-Werror` и санитайзерами. Поэтому разбор
форматов, конечные автоматы и вывод представлений вынесены в файлы без
зависимостей от ESP-IDF — новую логику добавлять туда. Браузерный JavaScript
проверяется под Node с рукописным поддельным DOM, без npm и сборщиков.

## Веб-интерфейс

| Точка | Назначение |
|---|---|
| `GET /api/status` | Состояние Wi-Fi и плеера одним снимком |
| `GET /api/playlist` | Список станций в CSV |
| `POST /api/playlist` | Замена списка станций целиком |
| `GET /api/usb` | Содержимое текущего каталога флешки |
| `POST /api/wifi` | Сохранение сети |
| `/ws` | Команды и живые обновления |

Команды WebSocket: `player.play`, `player.pause`, `player.toggle`,
`source.select`, `list.select`, `browse.up`, `wifi.save`. Живое состояние идёт
диффами; всё крупное — плейлист и каталоги USB — вынесено в REST, потому что не
помещается в кадр и не должно расходовать внутреннюю SRAM.

## Диагностика

Раз в 10 секунд прошивка пишет в журнал две строки о звуке — по одной на вывод
и на приём потока:

```
board: audio health: realtime=100% peak=21533 silent=0 zero_run=0 underruns=0
internet_radio: stream health: i2s_underruns=0 starvations=0 min_backlog=32768/65536 (1024ms) pcm=100%
```

Исправная картина: `realtime` 99–100 %, остальные счётчики нулевые. Если при
этом звука нет — неисправность после передачи в DMA, то есть в обвязке ЦАПа, а
не в прошивке. Отдельные предупреждения `audio gap`, `audio silence` и
`audio zero-run` фиксируют момент события, а `slow repaint` — проход
отрисовки, который не укладывается в 400 мс.

## Данные на устройстве

Раздел `littlefs` хранит и статику веб-интерфейса, и пользовательские данные:
`data/www/` (при сборке сжимается в gzip), `data/config/stations.csv`,
`data/config/settings.csv`, а также `wifi.json`, который создаёт само
устройство и который в Git не входит. Не добавляйте в репозиторий пароли и
ключи.

## Ограничения

- **Не более 256 записей в каталоге флешки.** Лишние отбрасываются с
  предупреждением; каждая запись стоит около 264 байт в PSRAM.
- **Только FAT32 или FAT16.** exFAT не собран, а флешки от 64 ГБ обычно
  приходят с завода в exFAT.
- **Веб-интерфейс рассчитан только на доверенную локальную сеть.**
  Аутентификации нет, `Origin` не проверяется. Наружу не открывать.
- Свободной внутренней SRAM мало. Крупные буферы выделяются в PSRAM с откатом
  во внутреннюю память — откат нужно сохранять при добавлении новых.

В `.vscode/tasks.json` есть задачи сборки, прошивки и монитора; они берут
`idf.py` из окружения терминала.
