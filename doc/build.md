# Сборка и прошивка

[← README](../README.md) · [English](build.en.md)

Есть два пути. **Быстрый** — залить готовый образ из релиза: ничего не
устанавливать, одна команда. **Полный** — собрать прошивку из исходников под
свою плату: нужна среда ESP-IDF, зато дисплей, распиновка и набор функций будут
ваши.

Что нужно знать в обоих случаях:

- **Плата прошивается через UART-порт, а не через USB-разъём.** USB-разъём
  на плате отдан флешке (USB Host), поэтому прошивка и журнал идут через мост
  USB-UART. В системе он виден как `/dev/ttyUSB0` или `/dev/ttyACM0` (Linux),
  `/dev/cu.usbserial-*` (macOS) или `COMn` (Windows). На модуле с двумя
  разъёмами нужен тот, что подписан UART или COM.
- **Кабель должен быть с проводами данных.** Кабель «только зарядка» питает
  плату, но порта в системе не появится — это самая частая причина «не
  прошивается».
- **Во флеше два независимых раздела: приложение и данные.** Приложение — это
  сама прошивка. Данные — веб-страницы, список станций, настройки, сети Wi-Fi.
  Обновление приложения данные не трогает; перезапись данных стирает всё, что
  устройство запомнило. Ниже это повторяется везде, где важно.

## Быстрый путь: готовый образ

1. Скачайте из [релиза](https://github.com/jmper-ha/jradio/releases) файл
   `jradio-<версия>-full.bin` — в нём вся флеш-память целиком: загрузчик,
   прошивка и раздел данных.
2. Установите `esptool`: `pip install esptool` (нужен Python 3).
3. Подключите плату к компьютеру кабелем к UART-порту и запишите образ:

   ```bash
   esptool.py --chip esp32s3 -p /dev/ttyUSB0 -b 460800 write_flash 0x0 jradio-v1.3.0-full.bin
   ```

   Под Windows порт — `COM3` и подобное. Если esptool не может подключиться,
   зажмите кнопку BOOT, коротко нажмите RESET, отпустите BOOT и повторите.

4. После записи плата перезагрузится и поднимет точку доступа `jradio-XXXX` —
   дальше см. [«Первое включение»](usage.md#первое-включение).

Готовый образ собран под конфигурацию по умолчанию из `board_options.h`:
дисплей ST7796S 480×320 и распиновка из [«Оборудования»](hardware.md). Если у
вас другой дисплей или другие выводы — нужен полный путь.

**Обновление до новой версии** без потери настроек — только приложение:

```bash
esptool.py --chip esp32s3 -p /dev/ttyUSB0 -b 460800 write_flash 0x20000 jradio-v1.3.0-app.bin
```

Раздел данных при этом остаётся вашим. Если релиз обновил и веб-интерфейс,
устройство скажет об этом на экране «Об устройстве» — тогда запишите ещё и
`jradio-<версия>-littlefs.bin` на смещение `0x620000`, предварительно сделав
резервную копию (см. [«Данные на устройстве»](#данные-на-устройстве)).

## Полный путь: сборка из исходников

### 1. Установите среду

ESP-IDF 5.5.x, цель `esp32s3`. Проект проверен на 5.5.5. Как поставить
VS Code с расширением ESP-IDF или голый ESP-IDF в терминале — в
[«Установке среды разработки»](toolchain.md). Дальше считается, что среда
стоит.

### 2. Опишите свою плату

Откройте [`board_options.h`](../board_options.h) в корне проекта. Это
единственный файл, который нужно править: в нём сказано, какие детали стоят и
на каких выводах.

```c
#define DISPLAY   DISPLAY_ST7796S_480_320   // какая панель и как она стоит
#define AUDIO_DAC DAC_PCM5102

#define TFT_CS_GPIO 10                        // и дальше — выводы
...
```

- **Дисплей** — одно из имён в
  [`board_parts.h`](../components/board/include/board_parts.h):
  `DISPLAY_ILI9341_320_240`, `DISPLAY_ST7789_240_320`,
  `DISPLAY_ILI9488_480_320`, `DISPLAY_ST7796S_320_480`,
  `DISPLAY_ST7789_320_170` и т. д. Порядок чисел в имени — это ориентация:
  `480_320` горизонтально, `320_480` вертикально.
- **Чего нет на плате — закомментируйте.** Нет слота microSD — уберите его
  блок, и карты не будет ни в меню, ни в веб-интерфейсе. Нет кнопок — уберите
  строки `BUTTON_*_GPIO`. Так же включаются необязательные вещи: ИК-приёмник,
  модуль Bluetooth, вывод MUTE усилителя, ключ питания периферии.
- **Функции без железа** — `YANDEX_MUSIC` и `DLNA` — включаются словами
  `FEATURE_ON` / `FEATURE_OFF`.

Опечатка в имени детали остановит сборку с понятной ошибкой — устройство с
неверной опцией не соберётся, а не будет молчать. Подробно о каждом блоке — в
[«Оборудовании»](hardware.md).

### 3. Соберите

В VS Code — `Ctrl+Shift+B`. В терминале с активированным ESP-IDF:

```bash
idf.py build
```

Первая сборка занимает несколько минут и **ходит в интернет**: менеджер
компонентов скачивает LVGL, кодеки и драйверы панелей, а компонент littlefs
ставит себе `littlefs-python` для сборки образа данных. Дальше всё лежит в
`managed_components/` и `build/`, и сеть не нужна.

Если сеть моргнула, сборка падает с сообщением вроде
`Could not find a version that satisfies the requirement littlefs-python` —
просто повторите `idf.py build`, докачается только недостающее. За прокси
отвечают обычные переменные pip: `PIP_INDEX_URL`, `PIP_PROXY`.

Результат — `build/jradio.bin` (приложение) и `build/littlefs.bin` (образ
данных).

### 4. Прошейте в первый раз: приложение и данные

На новой плате раздела данных ещё нет, поэтому первая прошивка пишет оба.
В VS Code — задача **Terminal → Run Task → ESP-IDF: First flash (app + data)**.
В терминале:

```bash
idf.py -p /dev/ttyUSB0 flash            # загрузчик, таблица разделов, приложение
idf.py -p /dev/ttyUSB0 littlefs-flash   # раздел данных
```

Порт — UART-порт платы (см. начало страницы). Если плата в системе одна,
задачи VS Code находят её сами; при нескольких укажите нужную переменной
`ESPPORT`.

Залито только приложение, без данных? Устройство загрузится, но экран
покажет пустоту, а веб-интерфейс не откроется. Допишите данные командой
`littlefs-flash`.

### 5. Посмотрите журнал

```bash
idf.py -p /dev/ttyUSB0 monitor          # выход: Ctrl+]
```

или задача **ESP-IDF: Monitor**. Что искать в журнале и как читать строки о
здоровье звука и памяти — в [«Диагностике»](diagnostics.md).

Порт занимает тот, кто открыл его первым: если прошивка не начинается, а лог
пуст, почти наверняка в другом окне открыт монитор.

### 6. Обновляйте только приложение

Поменяли код, собрали — заливайте приложение:

```bash
idf.py -p /dev/ttyUSB0 flash
```

Раздел данных остаётся нетронутым: список станций, сети, настройки, привязка
Яндекса и обученный пульт живут дальше. Это обычный рабочий цикл.

Раздел данных переписывают только когда изменился он сам — веб-страницы в
`data/www/` или список станций по умолчанию. Тогда — `littlefs-flash`, но
сначала резервная копия, см. ниже.

## Данные на устройстве

Раздел `littlefs` хранит вместе:

- веб-интерфейс — из `data/www/` (при сборке сжимается в gzip);
- список станций по умолчанию `data/config/stations.csv` и картинки станций
  `data/radio_img/`;
- настройки по умолчанию `data/config/settings.csv`;
- то, что создаёт само устройство: сети Wi-Fi `wifi.json`, токен Яндекса
  `yandex.json`, ключ погоды `weather.json`, таблицу пульта `remote.csv`,
  правки списка станций и настроек.

`littlefs-flash` **переписывает раздел целиком** — всё из последнего пункта
пропадает, устройство после прошивки поднимет точку доступа как новое. Поэтому
порядок такой:

1. **Скачайте резервную копию:** страница настроек → «Резервная копия» →
   «Скачать архив», или `curl -O -J http://<ip>/api/backup`. В архиве сети,
   настройки, токен Яндекса, ключ погоды и таблица обученных кнопок пульта.
2. **Сохраните список станций отдельно:** страница плейлиста → «Экспорт»,
   или `curl http://<ip>/api/playlist > stations.csv`. В архив он не входит.
3. Прошейте: `idf.py -p PORT littlefs-flash`.
4. **Восстановите:** «Резервная копия» → «Восстановить», или
   `curl -X POST --data-binary @jradio-*.zip "http://<ip>/api/restore?name=backup.zip"`.
   Устройство перезагрузится с прежними сетями и настройками.
5. Верните список станций через «Импорт» на странице плейлиста.

Таблица обученных кнопок пульта входит в копию и вернётся вместе с ней.

Всё, что лежит в `data/`, попадает в образ и на каждую плату, которую вы
прошиваете, — не кладите туда пароли, токены и ключи. Файлы устройства
(`wifi.json`, `yandex.json`, `weather.json`) в Git не входят.

## Версии и релизы

Версию прошивки не нужно вписывать руками: она берётся из `git describe` при
сборке и видна в журнале загрузки и на экране «Об устройстве». Ставьте теги —
без них версия превращается в короткий хеш, по которому не понять, какая
сборка новее:

```bash
git tag -a v1.4.0 -m "что нового"
git push origin v1.4.0        # обычный git push теги не отправляет
```

Новый тег подхватывается на следующей переконфигурации — после `git tag`
сделайте `touch CMakeLists.txt` и соберите заново.

У веб-интерфейса версия своя: он живёт в разделе данных и пишется другой
командой. Устройство показывает обе на экране «Об устройстве» и предупреждает,
если они разошлись, — тогда пора обновить раздел данных.

**Собрать релиз** — файлы для скачивания в `release/<версия>/`:

```bash
touch CMakeLists.txt && idf.py build
bash tools/release.sh
```

Скрипт складывает приложение, загрузчик, таблицу разделов, образ данных и
всё это одним файлом для записи на смещение 0, вместе с контрольными суммами и
инструкцией. Образ данных он собирает заново без `wifi.json`, `yandex.json` и
`weather.json` — чужая плата не должна получить ваши пароли. На грязном дереве
или при несовпадении версии в бинарнике с тегом скрипт отказывается работать.

## Тесты

```bash
bash tests/run_host_tests.sh
```

Запускается на Linux, macOS или WSL, ESP-IDF активировать не нужно (скрипт
сам находит его исходники cJSON). Тесты компилируют настоящие файлы компонентов
с `-Werror` и санитайзерами: разбор форматов, конечные автоматы, вывод экранов.
Браузерный JavaScript проверяется под Node без npm и сборщиков. Один тест
запускается своей строкой из скрипта или напрямую:
`node tests/test_web_playlist.js`.

## Если что-то пошло не так

| Что видно | Причина | Что делать |
|---|---|---|
| `Failed to connect to ESP32-S3` | кабель без данных, порт занят или плата не в режиме загрузки | сменить кабель; закрыть монитор; зажать BOOT, нажать RESET, отпустить BOOT |
| `Permission denied: '/dev/ttyUSB0'` (Linux) | пользователь не в группе порта | `sudo usermod -aG dialout $USER` и перелогиниться |
| `Could not find a version that satisfies the requirement littlefs-python` | моргнула сеть при сборке образа данных | повторить `idf.py build` |
| Экран пустой, веб не открывается, устройство при этом грузится | залито только приложение | `idf.py littlefs-flash` или задача «First flash» |
| Экран чёрный или картинка мусор | в `board_options.h` не та панель или ориентация | проверить `DISPLAY` и выводы TFT |
| Экран «Об устройстве» говорит, что версии разошлись | приложение обновили, данные — нет | резервная копия → `littlefs-flash` → восстановление |
| `idf.py: command not found` | среда не активирована в этом терминале | `source <idf>/export.sh` или задачи VS Code — см. [«Установку»](toolchain.md) |
