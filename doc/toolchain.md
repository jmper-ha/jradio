# Установка среды разработки

[← README](../README.md) · [English](toolchain.en.md)

Проект собирается ESP-IDF 5.5.x под цель `esp32s3`. Проще всего поставить всё
расширением ESP-IDF для VS Code: оно скачает и сам фреймворк, и компилятор.
Ручная установка описана в конце, она нужна только тем, кто собирает из
терминала без VS Code.

**Python поставьте сами и до расширения.** Расширение не приносит интерпретатор
с собой — оно создаёт себе окружение из уже имеющегося. Если его нет, установка
не отказывается сразу, а идёт с ошибками где-то в середине, и про Python в них
не говорится: под Windows это ловилось на практике, и лечилось именно тем, что
Python поставили руками. На Linux и macOS интерпретатор обычно уже есть, но в
списке пакетов ниже он всё равно назван первым — по той же причине.

## Что понадобится

- Linux, macOS или Windows 10/11, 64 бита.
- Около 5 ГБ на диске: ESP-IDF, тулчейн и каталог сборки.
- Интернет на установку и на первую сборку — дальше он не нужен.
- **USB-кабель с проводами данных.** Кабель «только зарядка» выглядит точно так
  же, и плата от него питается, но в системе не появляется никакого порта. Это
  самая частая причина «не прошивается».

## 1. Системные пакеты

### Linux (Debian, Ubuntu)

```bash
sudo apt update
sudo apt install -y git wget flex bison gperf python3 python3-pip python3-venv \
                    cmake ninja-build ccache libffi-dev libssl-dev dfu-util \
                    libusb-1.0-0
```

Нужен Python 3.9 или новее. `python3-venv` обязателен, и не только для самого
ESP-IDF: компонент littlefs создаёт себе ещё одно отдельное окружение, чтобы
собрать образ раздела данных, и без `venv` сборка падает не на установке, а
посреди сборки прошивки.

Дальше — доступ к последовательному порту без `sudo`:

```bash
sudo usermod -aG dialout $USER
```

и **перелогиниться**, иначе группа не применится. На Arch и Fedora группа может
называться иначе: посмотрите владельца порта командой `ls -l /dev/ttyACM0`.

### macOS

```bash
xcode-select --install
brew install cmake ninja dfu-util python
```

### Windows

Поставьте **Python с [python.org](https://www.python.org/downloads/windows/)**,
и при установке отметьте «Add python.exe to PATH». Именно это и есть тот шаг,
без которого установка ESP-IDF идёт с ошибками.

Отдельно проверьте, что `python` в консоли — это он, а не заглушка Microsoft
Store: наберите `python --version`. Если открывается магазин или версия не
печатается, выключите псевдонимы в «Параметры → Приложения → Дополнительные
параметры приложения → Псевдонимы выполнения приложения» — обе строки с
`python`.

Git и компилятор ставить не нужно, их приносит установщик ESP-IDF. Может
понадобиться драйвер моста USB-UART вашей платы — CP210x, CH34x или FTDI, —
если система не показывает COM-порт.

Одно ограничение: под Windows работают все задачи VS Code, кроме хостовых
тестов. Им нужны POSIX-shell и gcc с санитайзерами, то есть Linux, macOS или
WSL.

## 2. VS Code и расширение ESP-IDF

1. Поставьте [VS Code](https://code.visualstudio.com/).
2. Откройте в нём папку проекта. VS Code предложит рекомендованные расширения —
   `espressif.esp-idf-extension` и `ms-vscode.cpptools`; согласитесь. Список
   лежит в [`.vscode/extensions.json`](../.vscode/extensions.json), так что
   ничего искать в магазине не нужно.
3. Расширение при первом запуске само откроет мастер настройки. Если не
   открыл — `Ctrl+Shift+P` → **ESP-IDF: Configure ESP-IDF Extension** →
   **Express**.
   - **Версия:** `v5.5.5`. Проект собран и проверен на ней; подойдёт любая
     5.5.x, но начинать лучше с той же.
   - **Путь установки:** по умолчанию `~/esp/` на Linux и macOS,
     `%USERPROFILE%\esp\` на Windows. **Не выбирайте путь с пробелами или
     кириллицей** — часть инструментов тулчейна на них спотыкается, причём
     сообщения об ошибке будут говорить о чём угодно, кроме пути.
   - Мастер скачает ESP-IDF и тулчейн (около 2 ГБ) и создаст для них
     Python-окружение.
4. Дождитесь надписи об окончании установки. До неё сборка работать не будет.

Проверка, что всё встало: команда **ESP-IDF: Show Examples** должна открыть
список примеров.

## 3. Первая сборка и прошивка

- `Ctrl+Shift+B` — сборка.
- Остальное в **Terminal → Run Task**: `ESP-IDF: Flash`, `ESP-IDF: Monitor`,
  `Host tests`.
- **На чистую плату — `ESP-IDF: First flash (app + data)`.** Обычная прошивка
  пишет только приложение и не трогает раздел данных, а на новой плате его ещё
  нет: без веб-страниц и списка станций устройство поднимется, но покажет
  пустоту.

Цель `esp32s3` уже задана в проекте, `set-target` вызывать не нужно.

Задачи зовут [`tools/idf.sh`](../tools/idf.sh), а под Windows —
[`tools/idf.ps1`](../tools/idf.ps1). Скрипт сам находит установленный ESP-IDF,
в том числе поставленный расширением, и активирует его — запускать `export.sh`
руками не требуется. Порт определяется автоматически, если плата в системе
одна; если их несколько, укажите нужную переменной `ESPPORT`.

**Первая сборка ходит в интернет** и после установки среды: менеджер
компонентов скачивает LVGL, кодеки и драйверы панелей, а компонент littlefs
ставит себе `littlefs-python` с PyPI. Что при этом может пойти не так и как
читать сообщения — в [«Сборка и прошивка»](build.md).

## 4. Без VS Code, из терминала

```bash
mkdir -p ~/esp && cd ~/esp
git clone -b v5.5.5 --recursive https://github.com/espressif/esp-idf.git v5.5.5/esp-idf
cd v5.5.5/esp-idf && ./install.sh esp32s3
```

Дальше в каждой новой сессии терминала:

```bash
source ~/esp/v5.5.5/esp-idf/export.sh
cd путь/к/jradio
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

`export.sh` меняет только текущую сессию — это и есть то, как им положено
пользоваться. Не добавляйте его в `.bashrc`: он ставит свой Python впереди
системного, и это рано или поздно сломает что-нибудь постороннее.

## 5. Порт устройства

- **Linux:** `/dev/ttyACM*` или `/dev/ttyUSB*` — что именно, зависит от моста
  на плате. Надёжный способ узнать: `ls /dev/tty{ACM,USB}*` до подключения и
  после.
- **macOS:** `/dev/cu.usbserial-*` или `/dev/cu.usbmodem*`.
- **Windows:** `COM*`, номер виден в диспетчере устройств.

Порт занимает тот, кто открыл его первым. Если прошивка не начинается, а лог
пустой — почти наверняка в другом окне открыт монитор.

## 6. Если что-то пошло не так

| Сообщение | Что это | Что делать |
|---|---|---|
| Мастер расширения падает с ошибками на середине (наблюдалось под Windows) | нет системного Python, или в PATH заглушка Microsoft Store | поставить Python с python.org, отметить «Add to PATH», выключить псевдонимы Store и запустить мастер заново |
| `idf.py: command not found` | окружение не активировано | `source .../export.sh` в этой же сессии, либо собирать задачами VS Code |
| `Permission denied: '/dev/ttyACM0'` | пользователь не в группе порта | `usermod -aG dialout` и перелогиниться |
| `Failed to connect to ESP32-S3` | кабель без данных, порт занят или плата не в режиме загрузки | сменить кабель; закрыть монитор; зажать BOOT, коротко нажать RESET, отпустить BOOT |
| `Could not find a version that satisfies the requirement littlefs-python` | моргнула сеть при сборке образа данных | повторить `idf.py build`, докачается только недостающее |
| Экран пустой, устройство работает | залито только приложение | `ESP-IDF: First flash (app + data)` |

## 7. Что нужно не всем

**Node.js** нужен для трёх тестов браузерного JavaScript (`tests/*.js`) и для
[`tools/gen_ui_fonts.sh`](../tools/gen_ui_fonts.sh), который зовёт
`npx lv_font_conv`. Для обычной сборки не нужен: готовые шрифты лежат в
репозитории.

**Python-пакеты руками ставить не нужно** — речь именно о пакетах, а не о самом
интерпретаторе, который нужен и ставится первым. И ESP-IDF, и компонент
littlefs работают в своих окружениях, так что установка чего-либо в системный
Python на сборку не влияет.
